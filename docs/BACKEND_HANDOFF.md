# Backend Handoff Notes

- **Backend surface and contract status**: the FastAPI service exposes `GET /health`, `POST /api/search`, `POST /api/search-by-audio`, and `POST /api/classify-audio`; each endpoint already validates request shape (`query/top_k` JSON or multipart audio upload), and response models are defined so frontend integration can proceed against stable API contracts.
- **Current execution path and placeholder behavior**: all three inference endpoints are routed through a provider dispatch layer and currently use a placeholder provider that returns structured `501 Not Implemented` errors (`code` + `message`), so clients receive deterministic, machine-readable “model not connected” responses instead of fake success payloads.
- **Provider abstraction and swap boundary**: inference is isolated behind provider methods (`search_text`, `search_by_audio`, `classify_audio`) and route handlers depend only on that interface, so HTTP-layer logic (routing, serialization, status codes, validation) remains unchanged when inference implementation is swapped.
- **Technical work for CLAP integration**: next step is to add a real `ClapProvider` implementing the provider interface, including model/init loading (base or checkpoint), text/audio preprocessing, retrieval or classification inference, and output mapping into existing response schemas (`id/title/species/score` and optional metadata fields).
- **Activation path with no contract churn**: register the new provider in the factory, switch `MODEL_PROVIDER` from `placeholder` to `clap`, and configure model-related env vars (checkpoint/index paths) as needed; frontend endpoints and payload contracts remain identical, so rollout is a backend runtime change rather than a full-stack refactor.
